Structured data

How machines read this

Every page on this site carries JSON-LD structured data in its <head>. This page documents what that data declares and where each schema type appears.

The schema is not decoration. It is the primary output. The prose on each answer page is a human-readable rendering of the same structured evidence that lives in the markup.

Schema types in use

What is declared and where

Only types that are live on published pages are listed. Nothing planned or aspirational.

Type Declares Pages
DataCatalog The reference library as a curated, freely accessible collection of expert answers. Publisher is the Organization node. The WebSite node references it via about. Homepage
WebSite Site-level identity: name, URL, publisher, language. Anchor for cross-page @id references. Homepage
Organization Cited Conversations as a named entity, with sameAs linking to Ringmaster. Founder references the Person node. Homepage
Person Each named speaker: name, title, employer, and sameAs linking to their LinkedIn profile and company URL. One node per speaker per episode page. Homepage, episode pages
FAQPage The episode answer page as a structured set of question-and-answer pairs. Each pair is a Question with an acceptedAnswer carrying the speaker attribution and citation timestamp URL. Episode answer pages
PodcastEpisode The source recording: episode number, title, publish date, and a reference to the AudioObject and the PodcastSeries. Episode answer pages
AudioObject The audio file: content URL, embed URL, encoding format, duration, and upload date. Linked from PodcastEpisode via associatedMedia. Episode answer pages
Quotation One node per Q&A pair: the answer text attributed to the speaker, with a citation value pointing to the exact timestamp URL in the source recording. This is the claim-level evidence unit. Episode answer pages
WebPage / CollectionPage Page-level identity: URL, name, description, parent site reference, and breadcrumb. CollectionPage on the episode index; WebPage elsewhere. All pages
BreadcrumbList Page position in the site hierarchy. Three levels on episode answer pages: Home → Episodes → episode title. All pages except homepage

The citation field

What it is

Every Quotation node and every acceptedAnswer inside a FAQPage carries a citation field. Its value is a URL that opens the source podcast episode at the exact second the speaker said the answer being cited.

The URL format uses a query parameter, not a fragment, because the Transistor player responds to query parameters: 

https://podcast.citedconversations.com/<episode-slug>?t=<seconds>

// example: answer begins at 6 minutes 23 seconds
https://podcast.citedconversations.com/ep1-aeo-practice?t=383

Why it matters

A citation that resolves to a playable moment converts a claim from asserted to verifiable. An AI answer engine reading this page can report not only what was said and who said it, but where in a primary source the claim originates. That is a different class of evidence from uncited text.

No page ships without a tested, working citation URL for every claim. If a link does not seek to the correct moment, the page does not publish.

The complete Quotation node

Below is the structured data for a single claim, as it appears in the <script type="application/ld+json"> block on an episode answer page. 

{
  "@type":              "Quotation",
  "@id":               "https://citedconversations.com/episodes/<slug>/#quotation-1",
  "text":              "<the speaker's actual words>",
  "spokenByCharacter": { "@id": "...#speaker-<id>" },
  "creator":           { "@id": "...#speaker-<id>" },
  "dateCreated":       "2026-09-30",
  "isPartOf":          { "@id": "...#episode" },
  "citation":          "https://podcast.citedconversations.com/<episode-slug>?t=<seconds>"
}

Speaker attribution

Person nodes

Every named speaker on a page gets a Person node with a stable @id. The node carries their name, job title, employer (as an Organization), and sameAs links to their LinkedIn profile and company URL. These let crawlers resolve the speaker to a known public identity rather than treating the name as a bare string. 

{
  "@type":     "Person",
  "@id":      "https://citedconversations.com/episodes/<slug>/#speaker-casey-cheshire",
  "name":     "Casey Cheshire",
  "jobTitle": "Founder & CEO",
  "worksFor": {
    "@type": "Organization",
    "name":  "Ringmaster",
    "url":   "https://ringmaster.com"
  },
  "sameAs": [
    "https://linkedin.com/in/caseycheshire",
    "https://ringmaster.com"
  ]
}

Attribution is pre-established

Speaker identity is confirmed before recording begins, not inferred from the transcript afterward. The Person node reflects intake data, not a guess from audio analysis.

The DataCatalog node

The homepage declares a DataCatalog node identifying the site as a curated, freely accessible collection. Its publisher is the Organization node. The WebSite node references it via about. 

{
  "@type":               "DataCatalog",
  "@id":                "https://citedconversations.com/#datacatalog",
  "name":               "Cited Conversations",
  "description":        "A reference library of expert answers from recorded human
                         conversations. Every claim is attributed to a named speaker
                         and links to the exact moment it was said.",
  "url":                "https://citedconversations.com/",
  "inLanguage":         "en-US",
  "isAccessibleForFree": true,
  "publisher":          { "@id": "https://citedconversations.com/#organization" }
}

isAccessibleForFree: true reflects that the answer pages are publicly readable without a login, paywall, or registration. No dataset size, record count, or publication date is claimed — there is one episode recorded and not yet published.

Crawlers and access

robots.txt

All crawlers are explicitly permitted. The robots.txt file names AI answer engine bots by User-agent and allows them individually, then sets a global allow for everything else. 

# AI answer engine crawlers
User-agent: GPTBot
Allow: /

User-agent: OAI-SearchBot
Allow: /

User-agent: PerplexityBot
Allow: /

User-agent: ClaudeBot
Allow: /

User-agent: *
Allow: /

sitemap.xml

A sitemap at /sitemap.xml lists all published pages. Episode answer pages are added to the sitemap before each page is committed. The sitemap URL is declared in robots.txt.

JavaScript dependency

No content on this site requires JavaScript to render. The structured data is in <script type="application/ld+json"> tags in each page's <head>. The syntax-highlighted JSON-LD visible on episode pages is server-side HTML with CSS classes — no client-side highlighting library.
